# 2. Security, Legal & Compliance Requirements

## 2.1 Spanish Labor Law — Time Tracking Obligations
This is not a peripheral concern. The legal framework is a strong reason for GSPunch to exist and it directly shapes several system requirements, we afford all of this during the development phase.

The obligation in Spain is established in Real Decreto-ley 8/2019, which modified Article 34 of the Estatuto de los Trabajadores. Enforcement is handled by the Inspección de Trabajo y Seguridad Social (ITSS).

**Time Tracking during Sick Leave (Incapacidad Temporal - IT)**
Handling medical leaves requires specific system logic due to recent changes in Spanish legislation (Real Decreto 1060/2022). Since April 2023, employees are no longer required to physically hand their medical leave certificates to the employer; the INSS transmits this data directly.

### 2.1.1 Audit Trails
**Immutability and Audit Trails (Ley 11/2021 - Ley Antifraude)**
Spanish legislation strictly prohibits software that allows the manipulation or deletion of historical labor records without a trace. A database UPDATE or DELETE command cannot simply overwrite a user's clock-in time. If an HR Admin corrects a missed clock-out, the system must implement a strict Audit Trail. Both the original and corrected timestamps must be permanently recorded and visible to inspectors.

### 2.1.2 What the law currently requires and what is changing in 2026:

| Requirement | Current Status | From 2026 |
| :--- | :--- | :--- |
| **Daily clock-in and clock-out** | Mandatory since 2019 | Mandatory |
| **Format** | Paper or digital accepted | Digital only — paper and Excel will no longer be sufficient |
| **Record retention** | Minimum 4 years. | 4 years, digitally accessible |
| **Inspector access** | On request | Remote access for inspectors in real time, without prior request. |
| **Employee access** | On request | Immediate digital access |
| **Breaks and overtime** | Recorded | Must differentiate between effective hours, breaks, and overtime. |

### 2.1.3 What non-compliance costs:
In 2024 alone, the Labour Inspectorate imposed nearly €3 million in fines for time-tracking non-compliance, affecting more than 21,600 workers. The most common infractions were: complete absence of a time register, incomplete or manipulated records, excess working hours without compensation, and undeclared unpaid overtime.

## 2.2 Data Privacy — GDPR + LOPDGDD
Since GSPunch processes the personal data of employees in Spain, two regulations apply simultaneously: GDPR (EU 2016/679) and LOPDGDD (Spain's national implementation of GDPR). The supervisory authority is the Agencia Española de Protección de Datos (AEPD). 

Obligations and policies that directly shape system design:

| Obligation / Policy | Implication for GSPunch |
| :--- | :--- |
| **Data retention policies** | RDL 8/2019 mandates a minimum 4-year retention of time records. After this mandatory window, records must be deleted to comply with GDPR. |
| **Right of erasure vs. retention conflict** | The 4-year legal retention obligation overrides an employee's right to immediate erasure for time records specifically. |
| **Data minimisation** | Only collect what is strictly necessary: timestamp, user ID, IP, location metadata. No behavioral profiling. |
| **Geolocation limits (Art. 90 LOPDGDD)** | Since the app uses IP/Geofencing validation, employees must be explicitly informed. The system must only validate the location at the exact moment of clocking in/out. |
| **Right to Digital Disconnection** | GSPunch must not send automated push notifications or alerts to employees to clock in/out outside their registered working schedule. |
| **Biometrics Restriction (AEPD 2023)** | Processing biometric data (fingerprints/facial recognition) is generally unlawful in Spain. GSPunch avoids biometric hardware, relying strictly on TOTP and Geofencing. |
| **Mandatory Breach Reporting (Art. 33 GDPR)** | If there is a security breach, the company is legally obliged to notify the AEPD within 72 hours. GSPunch must have automated security logs to detect breaches instantly. |

## 2.3 Establish high-level cybersecurity standards

### 2.3.1 OWASP and ASVS
To ensure the application is secure against modern web vulnerabilities, the minimum security posture for GSPunch is aligned with **OWASP** (Open Worldwide Application Security Project, a globally recognized non-profit organization dedicated to software security) and **ASVS Level 1** (an industry-standard checklist used to test web application technical security controls. Level 1 establishes the baseline defense against the most common vulnerabilities).

| Security Layer | Standard Established | Technical Implementation |
| :--- | :--- | :--- |
| **Password storage** | Bcrypt (cost ≥ 12) or Argon2id | Never MD5, SHA1, or plaintext |
| **2FA** | TOTP (RFC 6238) | Mandatory for Admin roles — method TBD |
| **Session management** | Regenerate ID on privilege change | HttpOnly + SameSite=Strict cookie flags. 30-min inactivity timeout |
| **SQL Injection** | PDO prepared statements exclusively | Zero string concatenation in database queries |
| **XSS** | htmlspecialchars() on all output | Enforce Content-Security-Policy (CSP) header |
| **CSRF** | Synchronizer token on all forms | Per-session token, validated server-side |
| **Brute force** | Account lockout policy | Lockout after 5 failed attempts (duration TBD) |
| **Transport security** | HTTPS enforced in production | HSTS header active in non-dev environments |
| **Secrets management** | .env file pattern | .gitignore enforced from day one (never in version control) |

### 2.3.2 ISO Standards Compliance (ISO/IEC 27001 & ISO/IEC 27701) 
While OWASP dictates how to write secure code (the technical layer), ISO standards dictate how the system architecture and data are managed (the organizational layer). GSPunch aligns its architecture with international ISO standards to mathematically guarantee GDPR and LOPDGDD compliance:

* **ISO/IEC 27001 (Information Security Management System):** We base our system on this standard by implementing its mandatory technical controls: data encryption at rest, strict Role-Based Access Control (RBAC), and continuous vulnerability logging.
* **ISO/IEC 27701 (Privacy Information Management):** This is the privacy extension of 27001. We comply with it by enforcing "Privacy by Design", ensuring data minimization and guaranteeing the employee's right to export their own data.

**International Scalability:** Because ISO/IEC 27001 and 27701 are universally recognized frameworks, architecting GSPunch around them future-proofs the application. If the software expands outside of Spain, the underlying architecture will already be compliant with international laws equivalent to GDPR (such as the CPRA in California or the LGPD in Brazil), requiring minimal architectural refactoring.
