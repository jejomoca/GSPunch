# Define the roles for the system.

To make this decision the most important factor to take into account is how many users the app will have, whether it is a small team of 10 users and 1 HR admin or is an enterprise of many users (10+) with admins and multiple managers to oversee the staff. 

This project is built to simulate a company structure, managing a growing user base (10+), various departments, and different access roles.

What is the difference between them? The fundamental difference is the State Management (How the database stores the user’s identity) and Authorization Logic (how the backend evaluates what the user can do).

The reason why we decided to make the Manager a Standalone role is to deliberately sacrifice some flexibility in exchange for higher security, the ability to manage more employees, and better auditability. By keeping the Manager completely separate from a regular Employee, we prevent accidental privilege escalation. 

This exact same logic applies to the HR Admin. While a Manager is strictly locked to their own department, the HR Admin needs organization-wide access to pull global reports, not just their department, to correct attendance records, and oversee all staff. 

At the base of this architecture, the regular Employee role is stripped of all administrative rights. This perfectly minimizes the attack surface, ensuring that a compromised employee account can only ever expose their own personal data, never all the company. 

Finally, the Super Admin is in a completely different layer. IT staff manages the infrastructure, they ought to approve the HR credentials, their geopositioning, the Ips of all the personal. This could make a little bottleneck but it functioning is needed to keep on the security of a crucial tool.

---

### Roles Overview

| Role | Responsibilities | Access Level |
| --- | --- | --- |
| **Super Admin** | Platform configuration, organization management, global oversight | Full system |
| **HR Admin** | Employee management, attendance records, report generation | Organization-wide |
| **Manager** | Team attendance visibility, absence flagging | Department-level |
| **Employee** | Clock in/out, view own history, manage own profile | Personal only |
